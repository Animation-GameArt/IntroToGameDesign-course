Week 2 · [Lecture] Week 2

In one sentence
Every student keeps a second copy of their project somewhere other than the computer they work on, and checks that it's current every session.

What this topic is for

A lost project usually happens before midterm, and it's preventable. This topic sets one habit in Week 2 and checks it in person as part of the project setup check.

Key ideas

  • Choose one method and use it every session.
Key ideas
Method How Good for
Unity Version Control In Unity Hub, the project's ⋯ menu → Use Unity Version Control. At the end of each session, Window → Unity Version Control, write a comment, check in Students who work on more than one computer, and anyone who wants history to roll back to
SSD plus a second copy Work from an external SSD. Once a week, copy the project folder to a second device at home Students who prefer not to use an online service
  • An SSD alone is not a backup. It's the working copy. If it's lost or fails, the project is gone.
  • Avoid cloud-synced folders. Unity projects contain thousands of files that change constantly. Services such as OneDrive can lock or half-sync them, which corrupts projects.
  • The Library folder doesn't need backing up. Unity rebuilds it. Leaving it out makes copies much smaller and faster.
  • GitHub is optional. Students with their own GitHub account may use it on their own computers. It isn't used in the lab.

In class

  1. Show both methods once, start to finish.
  2. Make the backup part of the project setup check: each student shows how their project is backed up.
