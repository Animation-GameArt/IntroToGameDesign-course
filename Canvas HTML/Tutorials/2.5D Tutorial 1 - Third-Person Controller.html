In this tutorial you build a player in a 3D world, seen by a camera that follows from behind. The controls are relative to the player, often called tank controls:

2.5D Tutorial 1 — Third-Person Controller
Input Keyboard Gamepad What it does
Left and right A / D, or ← → Left stick, sideways Turn the player
Forward and back W / S, or ↑ ↓ Left stick, up and down Move the way the player faces, or back up
Jump Space South button Jump

Because the camera stays behind the player, "forward" on the stick is always "into the screen". Classic examples are the early Resident Evil and Tomb Raider games, and many kart and boat games.

2.5D usually means a game with 3D art whose movement is limited in some way. This tutorial gives you full 3D movement. Tutorial 2 limits it to a rail, which is where the 2.5D feel comes from.

Time: about one lab session.

Before you start

  • You're working in the course project you've used since week 2, version 0.13.0 or later. It has the 2D and the 3D scripts. Everything your 2D exercises taught carries over: the Input Reader, events, variables, Health, Checkpoints and the UI all work the same way in 3D.
  • The Console has no red errors.

Part 1 — A 3D scene

  1. File → New Scene, choose Basic (Built-in), and click Create. It comes with a camera and a Directional Light. (Despite the name, it works with the project's URP settings.)
  2. File → Save As… and save it as Assets/_Game/Scenes/Tutorial25D_Behind.unity.
  3. Select Main Camera. Check that Projection is Perspective. Under Rendering, set Renderer to Universal Renderer.

Why change the Renderer?
The course project draws its 2D scenes with the 2D Renderer, which lights sprites. 3D models need the Universal Renderer, which lights and shades 3D shapes. The project has both, and each scene's camera picks one. Your 2D scenes keep using the 2D Renderer.

The ground.

  1. GameObject → 3D Object → Plane. Name it Ground, Position 0, 0, 0, Scale 5, 1, 5. A plane is 10 units across, so this is 50 × 50.
  2. In Assets/_Game, create a folder Materials. In it, Create → Material twice: Ground (a dull green or grey) and Blocks (a bright color). Set each one's Base Map color. Drag Ground onto the plane.

Something to move around.

  1. Add four or five cubes (GameObject → 3D Object → Cube) with the Blocks material: a wall to walk around, a low box to jump onto (Scale 2, 1, 2), and a taller one (Scale 2, 2.5, 2) you can't jump onto.
  2. Add a ramp: a cube with Scale 2, 0.2, 6, Rotation -15, 0, 0, one end resting on the ground.

Grey boxes first
Level designers call this greyboxing: shapes and distances first, art later. It's the 3D version of the blocky levels you built in Exercise 04.

Part 2 — The player

The player is an empty parent with the controller, and children for the look. The parent's pivot is at the feet.

  1. GameObject → Create Empty. Name it Player, Position 0, 0, 0, and set its Tag to Player.
  2. Right-click Player → 3D Object → Capsule. Name it Body, Position 0, 1, 0. In its Inspector, remove the Capsule Collider (⋮ → Remove Component): the parent's controller is the collider.
  3. Right-click Player → 3D Object → Cube. Name it Nose, Position 0, 1.5, 0.45, Scale 0.3, 0.2, 0.4. Remove its Box Collider too. The nose shows which way the player faces.
  4. Select Player and Add Component → Collin Game → 3D → Tank Controller 3D. It adds a Character Controller, sized to fit the capsule (Height 2, Radius 0.4, Center 0, 1, 0), and fills in the Input field.
  5. Press Play. Turn with A and D, move with W and S, jump with Space. Walk up the ramp and jump onto the low box.

Why a Character Controller?
In 2D you used a Rigidbody 2D. A Character Controller is a collider made for players: it walks up slopes and small steps, slides along walls, and isn't pushed around by physics. The Tank Controller 3D moves it every frame and handles gravity itself.

  1. Drag Player into Assets/_Game/Prefabs to make it a prefab. Tutorial 2 uses it.

Part 3 — A camera that follows from behind

  1. GameObject → Cinemachine → Cinemachine Camera. Name it Follow Camera. The Main Camera gets a Cinemachine Brain for you.
  2. On Follow Camera, set Tracking Target to Player.
  3. Set Position Control to Follow. In the Cinemachine Follow component that appears:
Part 3 — A camera that follows from behind
Setting Value Why
Binding Mode Lock To Target With World Up The camera turns with the player, so it's always behind them, but never tilts
Follow Offset 0, 3, -6 3 units up, 6 behind
Position Damping 0.5, 0.5, 0.5 Lags a little behind movement, so it feels smooth
Rotation Damping (Y) 1.5 Swings round a little after the player turns
  1. Set Rotation Control to Rotation Composer. Set its Target Offset to 0, 1.5, 0, so the camera looks at the player's chest, not their feet.
  2. Press Play. Turn on the spot: the camera swings round to stay behind you.

Try each change, then put it back:

  • Follow Offset 0, 6, -4: a high, steep view.
  • Rotation Damping (Y) 0: the camera is locked behind the player. Turning feels stiff and can make people feel sick.
  • Binding Mode: Lazy Follow: the camera follows but doesn't turn with the player. Turn on the spot to see the difference.

Walls between the camera and the player
Walk behind the tall box with your back to it: the box hides the player. On Follow Camera, Add Extension → Cinemachine Deoccluder moves the camera in front of anything blocking the view.

Part 4 — Tune the feel

Select Player and try these in Play mode. Changes made in Play mode are lost when you stop, so write down the values you like.

Part 4 — Tune the feel
Setting Try You'll notice
Turn Speed 90, then 300 Slow turning feels heavy, like a tank; fast turning feels twitchy
Forward Speed 4, then 10
Backward Speed equal to Forward Speed Backing up feels too easy; most games make it slower
Acceleration · Deceleration 5 · 5 The player feels like they're on ice
Air Control 0 You can't change speed mid-jump
Jump Height 1, then 4
Short Hop Speed Kept 1 Every jump is full height, however briefly you press
Fall Gravity Multiplier 1, then 2.5 Floaty jumps, then snappy ones
Coyote Time 0 Walk off the low box and press Jump just too late

These are the same ideas you tuned in Exercise 03, now in 3D.

Part 5 — Coins, a hazard and a checkpoint

The course's Core scripts work in 3D with 3D colliders.

Data. In Assets/_Game/Data, create an Int Variable Coins.

A coin.

  1. GameObject → 3D Object → Cylinder. Name it Coin, Scale 0.6, 0.05, 0.6, Rotation 90, 0, 0, Position about 0, 1, 0 somewhere in the level.
  2. Give it a yellow material.
  3. On its Capsule Collider, tick Is Trigger.
  4. Add Component → Collin Game → Core → Collectible: Add To Coins, Amount 1.
  5. Make it a prefab and place several.

Health and falling off.

  1. On Player, add Health (Max Health 3) and Respawner.
  2. Create an empty Fall Zone at 0, -10, 0 with a Box Collider, Is Trigger ticked, Size 200, 1, 200, and Kill Zone. Falling off the ground now sends the player back to the start.
  3. Place a Checkpoint (an empty with a Box Collider trigger, Size 3, 3, 3, and Checkpoint) halfway through your level.

Show the coins. Drag in the course HUD as you did in Exercise 06, with a UI Variable Binder showing Coins.

Press Play: collect coins, fall off the edge, and come back at the checkpoint.

Check your work

  • Left and right turn the player; forward and back move the way the nose points.
  • Backing up is slower than going forward.
  • The player walks up the ramp, slides along walls, and jumps onto the low box.
  • A quick tap of Jump gives a short hop; holding it gives a full jump.
  • The camera stays behind the player and swings round smoothly after a turn.
  • Coins disappear and the count goes up.
  • Falling off the ground returns the player to the start, or to the checkpoint once it's been touched.
  • Esc pauses the game, and the player doesn't move while paused.

If something goes wrong

If something goes wrong
What you see What to do
Everything is flat, with no shading Set the Main Camera's Renderer to Universal Renderer (Part 1, step 3)
Everything is dark The scene needs a light: GameObject → Light → Directional Light
The player falls through the ground The ground needs a collider. A Plane has a Mesh Collider; don't remove it
The player floats, or sinks into the ground The Character Controller's Center should be half its Height (0, 1, 0 for Height 2), and the Body capsule at 0, 1, 0
The player is stuck or jitters on the spot The Body or Nose still has a collider. Remove them; only the Character Controller should collide
The player can't climb the ramp Make the ramp less steep, or raise the Character Controller's Slope Limit
Coins don't collect The coin's collider needs Is Trigger, and Player needs the tag Player
The camera is in front of the player Follow Offset Z must be negative, such as -6
The camera spins when the player turns Raise Rotation Damping (Y), or use Lazy Follow
"Input is empty" in the Console Drag InputReader from Assets/_Course/Core/Input into the controller's Input field
After respawning, the player is somewhere odd The Respawner sends the player to where they started the scene, or to the last Checkpoint. Start the player on solid ground
