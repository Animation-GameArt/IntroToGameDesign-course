# Week 15 — Studio: Release

**Also due:** Gold, by 11:59 PM the night before class: the finished game on a public itch.io page.

## Topics, expanded

**A store page that explains the game in ten seconds.** A visitor decides in seconds. The page needs the title, one sentence that says what the player does, and a screenshot of the game being played. Use the logline from the one-sheet; that's what it was written for. Controls go on the page too, since nobody reads them in the game.

**Screenshots and a description.** Three screenshots that show three different things: the main action, the game's best-looking moment, and something that shows progress or variety. A title screen isn't a screenshot of the game. The description is short: what it is, how to play, how long it takes, and credits.

**Final build checks.** Run the downloaded build on a different computer. Check that it starts at the menu, that every scene is in the build, that sound plays, and that it can be quit. Give the build a version number, 1.0, so a later fix can be told apart.

**What a post-mortem is.** A post-mortem is an honest review of a finished project, written for the next project's benefit. What went right, so it can be repeated. What went wrong, so it can be avoided. It isn't an apology and it isn't an advertisement. The most useful ones compare the plan with the result: the ten-pager's scope page against the released game.
