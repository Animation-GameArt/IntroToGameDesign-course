# Week 16 — Post-mortem presentations

**Also due:** the post-mortem slides, in Canvas by 11:59 PM the night before class, presented in class.

## Topics, expanded

**Running the presentations.** Five minutes each, timed, with two minutes of questions. Ask every presenter the same closing question: "What would you tell yourself in Week 3?" The answers are nearly always about scope, and hearing it from fifteen classmates lands harder than hearing it from an instructor.

**What to listen for.** The strongest post-mortems are specific. "I ran out of time" is a symptom. "I spent three weeks on a save system the game didn't need" is a finding. Push gently for the specific version. Praise honest accounts of what went wrong as much as polished results, because that honesty is the skill being practiced.

**What carries forward.** Each student leaves with a released game on a public page, a design document and a post-mortem: the start of a portfolio. The Group Project course starts from the same template and the same kits, so the scripts are already familiar and the new problem is working as a team. Close by asking what the class would change about the course itself, and write the answers down for next semester.

## Connecting it forward

The class's answers about the course feed directly into the next version of the scripts, the kits and these pages. Useful per-game scripts written this semester can be promoted into the kits for the next one.
