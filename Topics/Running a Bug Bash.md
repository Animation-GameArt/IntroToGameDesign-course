# Running a Bug Bash

**Week 14 · [[Lecture] Week 14](https://github.com/Animation-GameArt/IntroToGameDesign-course/blob/main/Class%20Pages/Week%2014%20-%20Lecture.md)**

> [!abstract] In one sentence
> Everyone tries to break everyone else's game, writes down exactly how, and each developer leaves with a list of what to fix before Gold.

## What this topic is for

At Beta the content is complete, so finding bugs is the most valuable thing classmates can do for each other. The bash fills each student's must-fix list for the final week.

## Key ideas

- **Others break games in ways their developer never would,** because they don't know which paths are safe.
- **Fifteen minutes per game,** then swap.
- **Try the edges:** pause at odd moments, press everything at once, go backwards, quit and restart, die in strange places, resize the window.
- **Every bug gets steps.** "It broke" is worthless. "Jump while paused, then resume: the player floats" is a gift.
- **Developers write, not defend.** No explaining during the bash.
- **Then triage.** Must fix, should fix, won't fix. See [Bug Triage and Cutting Scope](https://github.com/Animation-GameArt/IntroToGameDesign-course/blob/main/Topics/Bug%20Triage%20and%20Cutting%20Scope.md).
