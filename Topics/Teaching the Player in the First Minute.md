# Teaching the Player in the First Minute

**Week 12 · [[Lecture] Week 12](https://github.com/Animation-GameArt/IntroToGameDesign-course/blob/main/Class%20Pages/Week%2012%20-%20Lecture.md)**

> [!abstract] In one sentence
> A new player should learn the controls and the goal in the first minute, from the game itself, without the developer explaining.

## What this topic is for

Next week's playtesters won't get any help. This topic prepares students' openings so the playtest finds deeper problems than "I didn't know which button jumps."

## Key ideas

- **Teach, test, twist** applies to the opening most of all. See [Teach, Test, Twist](https://github.com/Animation-GameArt/IntroToGameDesign-course/blob/main/Topics/Teach%2C%20Test%2C%20Twist.md).
- **Let the player try the main action somewhere safe** before anything can hurt them.
- **Show the goal.** The exit, the target or the first objective should be visible or clearly pointed to.
- **Prompts beat paragraphs.** "Space to jump," shown next to the first gap, works better than a page of instructions on the title screen.
- **One idea at a time.** Don't introduce combat and jumping on the same screen.
- **Test it on someone who hasn't seen it.** Two minutes, in silence. See [Watching Someone Play](https://github.com/Animation-GameArt/IntroToGameDesign-course/blob/main/Topics/Watching%20Someone%20Play.md).

## In class

1. Play the first minute of each student's game as a new player would, on the class screen. The class says where they'd be confused.
